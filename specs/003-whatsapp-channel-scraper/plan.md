# Implementation Plan: WhatsApp Channels Job Link Extraction

**Branch**: `003-whatsapp-channel-scraper` | **Date**: 2026-09-27 | **Spec**: [`spec.md`](spec.md)

**Input**: Feature specification from [`specs/003-whatsapp-channel-scraper/spec.md`](spec.md)

## Summary

Integrate WhatsApp broadcast channel job link extraction directly into the existing WhatsApp import workflow in `backend/src/scraper/whatsapp_scraper.ts`. The implementation unifies ingestion sources into a tagged configuration (`type: 'group' | 'channel'`), enforces search input sanitization (clearing any active search input before typing each group/channel lookup), navigates to the Channels / Updates sidebar tab to locate and open followed channels (`Found The Job Alerts`, `Freshershunt`, `Job Update With FoundtheJob`), extracts whitelisted links using the virtualization feed collector, and aggregates deduplicated links from both groups and channels into the Admin Scraper UI.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js (ESM), Express 5  
**Primary Dependencies**: Playwright (`playwright`), Drizzle ORM, TanStack Query, Redux Toolkit, React 19  
**Storage**: File-based persistent browser context (`.whatsapp-session`), PostgreSQL (Neon) for jobs persistence  
**Testing**: Playwright locator test runner (`npm run test:locators:report`), CLI test suite (`npm run scrape:whatsapp`)  
**Target Platform**: Desktop browser admin interface (Chromium headless backend engine)  
**Project Type**: Fullstack web application with background browser automation engine  
**Performance Goals**: <5s per channel navigation, 100% domain whitelisting, seamless multi-source streaming updates  
**Constraints**: Zero interruptions on individual channel failures, strict URL deduplication, read-only feed handling, 100% clean search input state between transitions  
**Scale/Scope**: 4 default groups + 3 default channels (scalable to dozens of configured sources)
